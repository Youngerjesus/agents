# How to verify 

문제는 단일 정답이 존재하는 수렴적 문제와 정답이 모호한 발산적 문제로 나누어 져있음. 

수렴적 정답(결정론적 로직) 검증 전략: 
- 예시 기반 테스트 (EBT, Example-Based Testing):
    * 적합한 경우: 도메인 규칙이 명확한 비즈니스 로직, 데이터 1:1 매핑.
    * 장점: 테스트 코드 자체가 명세서 역할을 하며, 내부 구현이 아닌 '행동(Behavior)'을 검증할 때 리팩터링 내성을 가집니다.
    * 한계 (알려진 미지): 개발자가 인지하고 있는 입력값(예: 정상 케이스)만 검증되며, 예측하지 못한 엣지 케이스(Black Swan)에 취약합니다.
* 속성 기반 테스트 (PBT, Property-Based Testing) 도입
    * 명확한 규칙이나 대칭성이 존재하는 곳에서 유효 : 모든 유효한 입력에 대해 시스템이 항상 만족해야 하는 불변의 성질을 정의 
        * 왕복 변환(Round-Tripping)이 발생하는 곳: 직렬화/역직렬화(JSON 인코딩/디코딩), 압축 알고리즘, 암호화/복호화 모듈. ($f^{-1}(f(x)) = x$)
        * 수학적 연산 및 자료구조: 정렬 알고리즘(항상 오름차순이어야 함, 입력과 출력의 요소 개수가 동일해야 함), 집합 연산, 순서가 결과에 영향을 미치지 않는 교환법칙/결합법칙 검증.
        * 상태 기반 시스템 (Stateful Systems): 데이터베이스 CRUD 연산. 무작위 순서로 삽입, 수정, 삭제를 수행한 후 최종 데이터베이스의 상태가 무결성 제약 조건을 만족하는지 확인.
        * 파서(Parser) 및 컴파일러: 무작위로 생성된 추상 구문 트리(AST)나 코드가 구문 에러 없이 파싱되는지, 혹은 명확한 에러 코드를 반환하는지(Crash가 발생하지 않는지) 검증.
    * 장점: 
        * Edge case 자동 발견  
    * EBT의 한계를 보완하기 위해 무작위 데이터를 대량 주입하여 시스템의 강건성을 확인하는 보조 수단으로 활용합니다.

발산적/복잡한 정답 검증 전략 
* 정답이 정해져 있지 않거나 LLM과 같이 비결정론적인 출력을 내는 경우, 평가자의 주관이 개입되는 순방향($x \to y$) 검증을 피하고 객관적 지표를 활용해야 합니다.
* 왕복 엔지니어링 (Round-Trip Verification): $f^{-1}(f(x)) \approx x$
    * 결과물(y)을 다시 역함수로 돌려 원본 입력(x)과 비교합니다. 두 데이터 간의 거리를 측정하여 객관성을 확보합니다.
* 메타모픽 테스팅 (Metamorphic Testing):
    * 정확한 출력값은 몰라도, 입력값의 변화에 따라 출력값이 일관되게 유지해야 하는 '관계(Relation)'를 검증합니다. (예: 정렬 순서 불변성)
* 형식 검증 (Formal Verification & SAT Solvers):
    * 결과물이 Z3 Solver 등을 통해 논리적 제약 조건(Constraints)을 위배하지 않았음을 수학적으로 증명합니다.
* 속성 기반 테스팅 (Property-Based Testing): $\forall x, P(f(x))$
    * 구체적인 값이 아닌, 결과물이 반드시 가져야 할 불변의 성질(길이 감소, 필수 키워드 포함 등)을 검증합니다.
